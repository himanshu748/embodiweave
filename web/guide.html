Why FalkorDB is central

The graph is the agent’s working memory.

The planner depends on connected evidence, not just a list of models. If FalkorDB is unavailable, planning stops with a visible error.

Relationships answer the question

Which compatible starting point has measured transfer evidence for this mission? Which child did that trial produce, and did its complete, versioned validation clear the threshold?

The answer uses typed relationships, ancestry traversals and parameterized Cypher. The agent has read access through GRAPH.RO_QUERY; trusted tools append measured records.

Rebuildable, auditable evidence

Immutable JSON records are the recovery log. FalkorDB is the query and decision layer. Decisions store exact templates, parameters, returned record IDs and graph revision.

Final test results are kept outside the planning graph. Partial or custom evaluations cannot stand in for a complete canonical validation suite.

Reproduce locally

Real training. Your own next experiment.

Python 3.13, Docker, macOS or Linux. No GPU required. Try training on the live page. Use the local stack for larger budgets and custom experiments.

git clone https://github.com/himanshu748/embodiweave.git
cd embodiweave
docker compose up --build

Open http://127.0.0.1:8000/live.html. Docker starts the pinned CPU application and FalkorDB, with a persistent local evidence volume. Training works without a model API key. See the README for the unrestricted local development stack and optional model setup.

Checkpoint export bundles contain model weights, normalization, contract, records, Python source, source hashes, dependencies and a runnable evaluation command. New bundles use the repro-v3 suffix; historical bundles remain unchanged.

What this proves

Evidence, with its limits attached.

Demonstrated

  • A real LLM choosing MCP tools.
  • Real PPO checkpoints and measured simulator episodes.
  • FalkorDB evidence driving scratch versus parent selection.
  • A gate retaining the deployed policy after failed validation.
  • Equal budget comparisons, including a negative result.

Still preliminary

  • A 2D kinematic simulator, no physical robot.
  • Three training seeds per benchmark arm.
  • The new lineage passed validation but failed held-out target collisions.
  • No demonstrated efficiency or real world safety advantage.
  • Small checkpoint library; the selection rule was revised between experiments.
