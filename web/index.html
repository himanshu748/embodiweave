    Graph model
    
  
    Evidence lives in FalkorDB, decisions read it
    
  
    Authored world facts plus measured evidence appended from immutable records. Hover or focus a node to trace its relationships.
    
  
    
    
  
    
  
    
    
    
      
    One of the decision queries
    
      
    Which past trials from each candidate parent apply to this exact target, recipe, budget and contract.
    

    UNWIND $ids AS pid
MATCH (p:Policy {id:pid})
OPTIONAL MATCH (t:Trial)-[:FROM_PARENT]->(p)
WHERE t.threshold_id = $threshold
  AND t.recipe = $recipe AND t.budget = $budget
  AND (t)-[:TARGETS]->(:Family {id:$family})
  AND (t)-[:UNDER_CONTRACT]->(:Contract {id:$contract})
OPTIONAL MATCH (t)-[:PRODUCED]->(child:Policy)
RETURN pid AS policy_id, t.id AS trial_id,
       t.threshold_reached AS reached,
       t.steps_to_threshold AS steps_to_threshold,
       child.id AS child_id
    
    
    
    
    
      
    Why a graph
    
      
      
        
    • Transfer history is conditional. A past trial only counts if its target family, recipe, budget, threshold and contract all match, a relationship traversal through the evidence graph.
      • 
        
    • Contracts gate reuse. A checkpoint with a different ray order is rejected before ranking, with the differing fields named.
      • 
        
    • Every decision is provenance. The decision records the graph revision and the exact queries it read, so it can be replayed.
      • 
        
    • All 12 graph query templates are read-only and run through GRAPH.RO_QUERY, so the agent cannot write the graph.
      •
