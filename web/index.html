Inspect the recorded FalkorDB shortest-path query

The returned rehearsal ancestor was one hop away. The agent considered it alongside all 17 eligible origins and chose a different checkpoint. Unweighted distance does not predict safety.

MATCH (p:Policy {id:$policy})-[:USES_CONTRACT]->(c:Contract)<-[:USES_CONTRACT]-(a:Policy)
WITH p,a,shortestPath((p)-[:DERIVED_FROM*1..8]->(a)) AS path
WHERE path IS NOT NULL AND length(path) <= $max_hops AND a.status = 'completed'
MATCH (a)<-[:ASSESSED]-(e:Evaluation)-[:ON_SUITE]->(s:Suite {id:$suite})
WHERE s.role = 'validation' AND e.complete_suite = true AND e.artifact_hash = a.artifact_hash
  AND e.suite_fingerprint = s.fingerprint AND e.success_rate >= $min_success
  AND e.collision_rate <= $max_collision
RETURN a.id AS ancestor_id, a.artifact_hash AS artifact_hash, length(path) AS hops,
       [n IN nodes(path) | n.id] AS path, e.id AS evaluation_id,
       e.success_rate AS success_rate, e.collision_rate AS collision_rate
ORDER BY hops, collision_rate, ancestor_id LIMIT 20

The fixed gate passed 4/4 suites. Target collisions rose from 2/60 to 3/60; crossing rose from 0/40 to 1/40. This run demonstrates the complete agent-to-training workflow. It does not establish a safety improvement, so the current demo policy stayed unchanged.

How it works

From graph evidence to a tested checkpoint

The LLM picks each tool call over MCP. Trusted code enforces contracts, budgets and the gate, and every outcome is written back to the graph.

  1. 1ObserveInspect the checkpoint’s measured validation, recorded failures and semantic contract.
  2. 2QueryRead-only Cypher templates over lineage, semantic contracts and matched validation.
  3. 3DecideThe model proposes an eligible origin. The guardrail checks its evidence and can veto it before training.
  4. 4TrainOne bounded PPO run from the chosen start. No retries to chase a better number.
  5. 5MeasureRetained-behaviour suites, tied to the exact artifact hash of the new checkpoint.
  6. 6GateRecord the fixed gate verdict. Passing validation does not automatically replace the demo policy.

Graph model

The graph supplies the evidence for the next action.

Contracts, lineages, trials and exact-artifact evaluations connect the facts an origin choice needs. A Decision records what the agent read before training starts. Hover or focus a node to trace its relationships.

Why a graph

  • An origin needs connected evidence. Its semantic contract must match, and its complete validation must assess the exact artifact. Lineage traversal supplies another starting point for the agent to inspect.
  • Contracts gate reuse. A checkpoint with a different ray order is rejected before ranking, with the differing fields named.
  • Every decision is provenance. The decision records the graph revision and the exact queries it read, so it can be replayed.
  • Reads and actions have separate boundaries. Read tools run GRAPH.RO_QUERY. Trusted action code records Decisions and launches only the consented, guarded training job.
